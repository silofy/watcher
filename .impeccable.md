# The Watcher — Frontend Design

## Design Context

### Users
Offensive-security practitioners reviewing a just-finished hacking session — HTB/THM players,
students, CTF competitors, junior SOC/pentest analysts. They review late, in a terminal-heavy
setting, often right after rooting a box. They live on Discord and GitHub and have a finely-tuned
BS detector — hype and fake polish lose them instantly. The job: see where they flowed, panicked,
and wasted time; learn from it; and flex a clean report to peers.

### Brand Personality
Precise · mechanical · unimpressed. A flight-data-recorder that tells you the truth without
flattering you — the cockpit voice recorder, not a cheerleader. Deep indigo ground and a teal-green
readout lamp. Confident, dense, calm.

### Aesthetic Direction — "God Tier debrief"
Take the flight-data-recorder metaphor literally. Dark, **deep-indigo** ground (#0a081b, tinted
toward hue ~287, never neutral gray, never pure black). A semantic accent system rather than one
lamp: **teal-green = on-path / good**, **cyan / lavender = alternative or neutral**, **coral =
deviation / time lost / warning**, **cool slate = absence (skipped, idle)**. The four actor modes
are a **calibrated instrument legend** (consistent OKLCH lightness + chroma) in lavender / teal /
coral / slate — not a neon dashboard. Type: **Saira** for equipment-label headlines, **Hanken
Grotesk** for humanist body, **Spline Sans Mono** for genuine machine readouts (timecodes, command
lines, gauge numbers) — never mono as decoration. Palette source: the user's "God Tier" terminal
scheme.

- **Theme:** dark (garage-at-9pm, post-session, terminal-adjacent).
- **Anti-references:** generic dark admin dashboard; purple→blue gradients; glassmorphism; neon
  glow; rounded-card grids; gradient text; monospace as a "technical" costume. (Cyan is in-palette
  here but used sparingly + purposefully, never as a default glow.)

### Layout — "Command console" (Antimetal-inspired)
Dense, hairline-ruled, low-chrome — a financial-terminal feel. A **sticky KPI strip** (grade +
load-bearing metrics as tabular-mono numbers) is always visible for side-eye glancing; below it a
**slim identity line**, the **deviation timeline** as the hero (with a cursor crosshair), then
**ledger tables** (path-vs-write-up, command log) and the deeper instruments. Sections are flat
(`Section`: label + hairline rule, no bordered card); numbers are the hero (`.readout`, `.mono`,
tabular-nums); ledger rows via `LedgerRow`/`LedgerHead`. Skeuomorphic arc gauges retired in favor of
numeric KPI cells.

### Design Principles
1. **Instrument, not dashboard.** Every metric reads like a calibrated readout with units, not a
   floating big number.
2. **Color carries meaning.** Coral is rare and load-bearing (deviation, time lost, warnings); teal
   means on-path. The indigo ground stays quiet so the accents land.
3. **Truth over flattery.** Copy is direct and specific; no hype. The BS detector must trust it.
4. **The machine is the hero.** A report instantly reads as "this is *Optimum*" — real HTB
   identity (name, avatar, difficulty, OS) anchors the hero.
5. **Present vs. past.** The latest run is foregrounded as the live debrief; history is a calm,
   browsable archive of prior machines.
